# Developer Insight

## Topic

Git Rebase vs. Merge for Feature Branches

## Explanation

When integrating changes from a base branch into your feature branch, `git merge` creates a new commit that ties the two histories together, preserving the exact chronological sequence. In contrast, `git rebase` temporarily removes your local commits, fast-forwards your branch to the latest tip of the base branch, and then reapplies your commits sequentially on top. This results in a clean, linear history without redundant merge commits, making future debugging easier.

## Practical Example

Instead of running this, which clutters history with merge commits:
```bash
git checkout feature-branch
git merge main
```

Run this to keep your feature branch history cleanly stacked on the latest main:
```bash
git checkout feature-branch
git rebase main
```

## Takeaway

Use `git rebase` on local feature branches to maintain a clean, readable commit history before opening a pull request. Never rebase public or shared branches, as rewriting history will disrupt your teammates' workflows.
