# Developer Insight

## Topic

Using `git worktree` for Parallel Branching

## Explanation

Switching context between different branches in a single Git repository often requires stashing changes, running builds, or reinstalling dependencies. `git worktree` allows you to check out multiple branches of the same repository into separate directories simultaneously. This means you can run tests on a hotfix in one folder while actively coding a feature in another, all sharing the same local `.git` database.

## Practical Example

To check out an existing branch into a new sibling directory named `hotfix-login`:
```bash
git worktree add ../hotfix-login hotfix-login
```
To clean up the worktree once the branch is merged and deleted:
```bash
git worktree remove ../hotfix-login
```

## Takeaway

Use worktrees when you need to jump between unrelated tasks instantly without losing your current working state or IDE context. It completely eliminates the friction of `git stash` and repeated dependency installs.
