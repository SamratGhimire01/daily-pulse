# Developer Insight

## Topic

Using `git worktree` for Parallel Feature Development

## Explanation

`git worktree` allows you to check out multiple branches of the same repository into separate directories simultaneously. Instead of constantly stashing changes, committing WIP code, or spinning up a second clone of a repo, worktrees share the same `.git` database. This means you can instantly jump to hotfix a production bug in one directory while your main feature branch remains completely untouched in another.

## Practical Example

To create a new worktree for a bugfix branch outside your current repo directory:

```bash
git worktree add ../hotfix-login bugfix/login-crash
```

To list all active worktrees:

```bash
git worktree list
```

Once you are done and the branch is merged, clean it up with:

```bash
git worktree remove ../hotfix-login
```

## Takeaway

Worktrees save disk space and context-switching overhead by letting you maintain multiple active workspaces for a single repository. It is an ideal workflow when you need to review a pull request or patch a bug without disrupting your current coding flow.
