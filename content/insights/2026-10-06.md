# Developer Insight

## Topic

Git Rebase vs. Merge for Feature Branches

## Explanation

When integrating changes from a base branch into your feature branch, `git merge` creates a commit node that preserves the exact historical timeline of both branches. Conversely, `git rebase` rewrites your feature branch's history by moving its base to the tip of the target branch, resulting in a clean, linear history. While rebase avoids messy merge commit graphs, it rewrites shared history and can cause confusing conflicts if others are working on the same branch.

## Practical Example

To safely update your current feature branch (`feature-login`) with the latest changes from `main` without creating a clutter of merge commits:

```bash
git checkout feature-login
git fetch origin
git rebase origin/main
```

## Takeaway

Use `git rebase` locally to keep your private feature branch history clean and linear before opening a pull request. Never rebase a public shared branch (like `main`), as rewriting history will disrupt your teammates' local repositories.
