# Developer Insight

## Topic

Git Rebase vs. Merge: Keeping History Clean

## Explanation

When integrating changes from a feature branch into main, `git merge` creates a merge commit that preserves the exact chronological history of your work. In contrast, `git rebase` rewrites your branch history by moving your commits to the tip of the main branch, resulting in a linear, easy-to-read project timeline. While merge is safer for shared public branches, rebase keeps local feature histories clean before final integration.

## Practical Example

```bash
# Update your local main branch
git checkout main
git pull

# Switch to your feature branch and rebase onto main
git checkout feature-branch
git rebase main

# Push the clean, linear history (force-with-lease is required after rebasing)
git push origin feature-branch --force-with-lease
```

## Takeaway

Use `git rebase` on your local feature branches to squash clutter and maintain a linear commit history, but avoid rebasing branches that other developers are actively working on.
