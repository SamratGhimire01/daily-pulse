# Developer Insight

## Topic

Git Rebase vs. Merge for Feature Branches

## Explanation

When integrating changes from a base branch into your feature branch, using `git merge` creates a merge commit that preserves the exact historical timeline of both branches. Conversely, `git rebase` rewrites history by moving your feature branch's base to the tip of the target branch, resulting in a clean, linear history without extraneous merge commits. Understanding when to use each prevents messy commit graphs while avoiding broken collaborative workflows.

## Practical Example

```bash
# Update your local main branch
git checkout main
git pull origin main

# Switch to your feature branch and rebase on top of main
git checkout feature/user-auth
git rebase main
```

## Takeaway

Use `git rebase` for local feature branches to keep your commit history clean before opening a pull request, but avoid rebasing shared public branches where others are actively collaborating.
