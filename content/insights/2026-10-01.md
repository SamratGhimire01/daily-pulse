# Developer Insight

## Topic

Git Rebase vs. Merge for Feature Branches

## Explanation

When integrating changes from a main branch into a feature branch, `git merge` creates a new merge commit that preserves the complete historical timeline of both branches. In contrast, `git rebase` temporarily moves your local feature branch commits aside, replays the latest main branch commits, and then reapplies your feature commits sequentially on top. This results in a clean, linear project history without extraneous merge commits, though it rewrites history and requires care on shared branches.

## Practical Example

To update your current feature branch with the latest changes from main cleanly, run:

```bash
git checkout feature-branch
git fetch origin
git rebase origin/main
```

## Takeaway

Use `git rebase` for your local feature branches to maintain a tidy, readable commit history before opening a pull request. Avoid rebasing branches that other developers are actively working on to prevent disruptive history rewrites.
