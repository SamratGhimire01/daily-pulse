# Developer Insight

## Topic

Git Rebase vs. Merge for Feature Branches

## Explanation

When integrating changes from a base branch into your feature branch, using `git merge` creates a merge commit that preserves the exact historical timeline, which can clutter log graphs. Conversely, `git rebase` temporarily removes your local commits, fast-forwards your branch to the latest upstream tip, and replays your commits sequentially on top. This results in a clean, linear history that makes debugging and code reviews much easier.

## Practical Example

Instead of running `git merge main` while on your feature branch, use:
```bash
git checkout feature-branch
git fetch origin
git rebase origin/main
```
If conflicts occur, resolve them, run `git add <file>`, and simply type `git rebase --continue` to finish the replay.

## Takeaway

Use `git rebase` for private feature branches to maintain a pristine, linear commit history before opening a pull request. Avoid rebasing shared branches where other developers are actively contributing to prevent disrupted commit hashes.
