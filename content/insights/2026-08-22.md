# Developer Insight

## Topic

Git Rebase vs. Merge for Feature Branches

## Explanation

When integrating changes from a base branch into your feature branch, `git merge` creates a new commit that ties the two histories together, preserving the exact chronological sequence. Conversely, `git rebase` rewrites history by lifting your feature commits and placing them on top of the latest base branch, resulting in a clean, linear project history without extraneous merge commits. However, rewriting history can disrupt collaborators if the branch is already shared publicly.

## Practical Example

```bash
# Update your local main branch
git checkout main
git pull

# Switch to your feature branch and rebase onto main
git checkout feature-branch
git rebase main
```

## Takeaway

Use `git rebase` on local, unshared feature branches to keep your commit history clean and readable. Never rebase public branches that other developers are actively working on.
