# Developer Insight

## Topic

Git Rebase vs. Merge for Feature Branches

## Explanation

When integrating changes from a base branch into your feature branch, `git merge` creates a new commit that preserves the exact history of both branches, making it clear when branches converged. Conversely, `git rebase` temporarily removes your local feature commits, fast-forwards your branch to the latest base commit, and then replays your changes sequentially on top. This results in a clean, linear project history without superfluous merge commits, but it rewrites history and requires caution on shared branches.

## Practical Example

```bash
# While working on your feature branch, pull and rebase onto main
git checkout feature-branch
git fetch origin
git rebase origin/main
```

## Takeaway

Use `git rebase` for local feature branches before opening a pull request to maintain a clean history, but avoid rebasing branches that other developers are actively collaborating on.
