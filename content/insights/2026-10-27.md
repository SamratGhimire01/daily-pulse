# Developer Insight

## Topic

Git Rebase vs. Merge for Feature Branches

## Explanation

When integrating changes from a base branch into your feature branch, `git merge` creates a commit record that preserves the exact history of when branches diverged and combined. Conversely, `git rebase` rewrites your feature branch's history by moving its base to the tip of the target branch, resulting in a clean, linear commit graph. While linear history is easier to read, rebasing public branches can disrupt collaborators by altering shared commit hashes.

## Practical Example

To cleanly update your feature branch with the latest changes from `main` without creating a merge bubble, run:

```bash
git checkout feature-branch
git fetch origin
git rebase origin/main
```

## Takeaway

Use `git rebase` locally to keep your private feature branch up to date and your history clean, but stick to `git merge` once code has been pushed to a shared remote repository to avoid breaking your team's workflow.
