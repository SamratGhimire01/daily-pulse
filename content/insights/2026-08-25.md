# Developer Insight

## Topic

Git Rebase vs. Merge for Feature Branches

## Explanation

When integrating changes from a main branch into your feature branch, using `git merge` creates a merge commit that preserves the exact historical timeline of both branches. Conversely, `git rebase` temporarily removes your local commits, fast-forwards your branch to the latest main commit, and then reapplies your commits sequentially on top. While rebasing results in a cleaner, linear history without extraneous merge commits, it rewrites history and requires force-pushing, which can disrupt collaborators if not handled carefully.

## Practical Example

To cleanly update your feature branch (`feature-xyz`) with the latest changes from `main` without creating a messy merge commit graph:

```bash
git checkout feature-xyz
git fetch origin
git rebase origin/main
```

## Takeaway

Use `git rebase` on private feature branches to maintain a pristine, linear commit history, but always use `git merge` on shared branches to avoid disrupting your team's commit references.
