# Developer Insight

## Topic

Git Rebase vs. Merge for Feature Branches

## Explanation

When integrating changes from a base branch into your feature branch, `git merge` creates a commit node that preserves the exact historical timeline of both branches. Conversely, `git rebase` rewrites your feature branch's history by moving its starting point to the tip of the base branch, applying your commits sequentially on top. While merge is safer for public shared branches because it avoids altering history, rebase keeps the commit log linear and clean for code review.

## Practical Example

Instead of running `git merge main` while on your feature branch, use rebase with autosash to keep things tidy:

```bash
git checkout feature-branch
git fetch origin
git rebase -i origin/main
```

## Takeaway

Use `git rebase` locally to maintain a clean, linear history before pushing your feature branch for review, but avoid rebasing shared branches where other developers are actively contributing.
