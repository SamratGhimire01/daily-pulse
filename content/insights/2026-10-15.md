# Developer Insight

## Topic

Git Rebase vs. Merge: Keeping Feature Branches Clean

## Explanation

When updating a feature branch with changes from the main branch, using `git merge` creates a merge commit that clutters the project history with non-functional integration points. Conversely, `git rebase` temporarily removes your local commits, applies the latest changes from the upstream branch, and then reapplies your commits sequentially on top. This maintains a linear, easy-to-read commit history that simplifies code reviews and debugging.

## Practical Example

```bash
# While working on your feature branch, pull and rebase onto main
git checkout feature-branch
git fetch origin
git rebase origin/main

# If conflicts occur, resolve them, then continue the rebase:
git add <resolved-files>
git rebase --continue
```

## Takeaway

Use `git rebase` for local feature branches before opening a pull request to keep history clean, but avoid rebasing shared public branches where others are actively collaborating.
