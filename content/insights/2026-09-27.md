# Developer Insight

## Topic

Using `git worktree` for Parallel Feature Development

## Explanation

The `git worktree` command allows you to check out multiple branches of the same repository into separate directories on your disk. Instead of constantly stashing changes, committing WIP code, or spinning up a second clone of a repo to review a pull request, worktrees link multiple working directories to a single shared `.git` object database. This means branches can be edited, built, and tested simultaneously without interfering with one another.

## Practical Example

To check out an existing branch into a new parallel directory named `hotfix-login` alongside your current project:

```bash
git worktree add ../hotfix-login bugfix/login-crash
```

Once you finish your work and remove the directory (`rm -rf ../hotfix-login`), clean up the worktree reference with:

```bash
git worktree prune
```

## Takeaway

Use worktrees when you need to jump between long-running tasks or hotfixes without disrupting your current coding state or running build processes. It saves disk space over multiple clones and eliminates context-switching friction.
