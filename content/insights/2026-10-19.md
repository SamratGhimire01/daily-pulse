# Developer Insight

## Topic

Git Rebase vs. Merge for Feature Branches

## Explanation

When integrating changes from a base branch into your feature branch, `git merge` creates a commit node that preserves the exact historical timeline of both branches. Conversely, `git rebase` rewrites your feature branch's history by moving its base to the tip of the target branch, resulting in a clean, linear commit history without extraneous merge commits. While rebasing makes code reviews easier, it should never be performed on shared remote branches where other developers are actively working.

## Practical Example

```bash
# Update your local main branch
git checkout main
git pull origin main

# Switch to your feature branch and rebase onto main
git checkout feature-auth
git rebase main
```

## Takeaway

Use `git rebase` locally before opening a pull request to keep your commit history clean and linear, but default to `git merge` for shared public branches to avoid disrupting your team's workflow.
