# Developer Insight

## Topic

Git Rebase --autostash

## Explanation

When switching branches to pull urgent fixes, you often hit a roadblock if you have uncommitted local changes that conflict with the target branch. Using `git stash` manually before switching and `git stash pop` afterward adds unnecessary friction to your workflow. The `--autostash` flag automates this entire lifecycle by stashing your dirty working directory right before the rebase begins and applying it back immediately after.

## Practical Example

Instead of running three separate commands:
```bash
git stash
git pull --rebase origin main
git stash pop
```
You can combine them into a single, atomic operation:
```bash
git pull --rebase --autostash origin main
```
You can also set this as a permanent default for all rebases on your machine:
```bash
git config --global rebase.autostash true
```

## Takeaway

Enable global autostash to eliminate the repetitive chore of manual stashing during pull requests and rebases. It keeps your workspace clean without risking the loss of work-in-progress code.
