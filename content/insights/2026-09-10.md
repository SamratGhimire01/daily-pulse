# Developer Insight

## Topic

Git Rebase vs. Merge for Feature Branches

## Explanation

When integrating changes from a base branch into your feature branch, `git merge` creates a commit that ties both histories together, which can clutter your project log with non-functional merge commits. Conversely, `git rebase` rewrites your feature branch's history by placing its unique commits on top of the latest base branch commits, resulting in a clean, linear history. However, you should never rebase commits that have already been pushed to a shared remote, as it forces other contributors to reconcile divergent histories.

## Practical Example

Instead of running:
```bash
git checkout feature-branch
git merge main
```

Use rebase for a clean local history:
```bash
git checkout feature-branch
git fetch origin
git rebase origin/main
```

## Takeaway

Use `git rebase` to keep your local feature branch history clean and linear before opening a pull request. Reserve `git merge` for combining public branches where preserving the exact historical record of integration is critical.
