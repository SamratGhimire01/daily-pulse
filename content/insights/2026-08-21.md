# Developer Insight

## Topic

Git Rebase vs. Merge for Feature Branches

## Explanation

When integrating changes from a base branch into your feature branch, `git merge` creates a commit that ties the two histories together, preserving exact chronological context. Conversely, `git rebase` rewrites your feature branch's history by moving its base to the tip of the target branch, resulting in a linear commit history. While linear histories are cleaner to read, rebasing public branches can disrupt collaborators by altering shared commit hashes.

## Practical Example

To cleanly update your current feature branch (`feature-auth`) with the latest changes from `main` without creating unnecessary merge commits:

```bash
git checkout feature-auth
git fetch origin
git rebase origin/main
```

## Takeaway

Use `git rebase` locally to keep your feature branch up-to-date and maintain a clean, linear history before opening a pull request. Always avoid rebasing branches that other developers are actively working on.
