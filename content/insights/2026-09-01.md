# Developer Insight

## Topic

Git Rebase vs. Merge: Keeping Feature Branches Clean

## Explanation

When updating a feature branch with changes from the main branch, using `git merge` creates a merge commit that clutters the project history with non-functional merge nodes. In contrast, `git rebase` temporarily removes your local commits, applies the latest changes from the target branch, and then reapplies your commits sequentially on top. This results in a linear, readable project history that makes debugging and code reviews significantly easier.

## Practical Example

```bash
# Switch to your feature branch
git checkout feature/user-auth

# Fetch the latest changes and rebase your branch on top of main
git pull origin main --rebase

# If conflicts arise, resolve them, then continue the rebase:
git add .
git rebase --continue
```

## Takeaway

Use `git rebase` for local feature branches before opening a pull request to maintain a clean, linear commit history. Avoid rebasing shared public branches, as rewriting history will disrupt your teammates' workflows.
